底层核心结构先回顾（这四个系统调用全都围绕这三张表）：

1. **进程文件描述符表**（每个进程独有）：下标 = fd，指向内核的文件表项
2. **文件表项（file 结构，内核全局）**：文件偏移量、打开模式（r/w/a）、引用计数、指向 inode 指针
3. **inode（索引节点，磁盘 + 内存 inode）**：文件元数据（大小、权限、磁盘块号、类型等，**不含文件名**）

> 
> 文件名存在目录项（目录块）里，目录项：文件名 → inode 号

---

## 1. open(pathname, flags, mode)

作用：**打开文件，建立进程和文件的联系，返回文件描述符 fd**

> 
> 不是把文件读到内存！很多人踩这个坑。

执行步骤：

1. 根据传入的文件路径`pathname`，逐层检索**目录项**，找到对应的 inode 号
2. 在内存中加载该文件对应的 **inode（内存 inode）**，检查权限：当前进程是否满足 open 指定的 flags（读 / 写），权限不满足直接报错返回
3. 在内核**全局文件表**里，新建一个文件表项：
   - 文件偏移量 offset 初始值：读 / 写打开默认 0；追加 O_APPEND 时写偏移每次写前跳到文件末尾
   - 记录打开标志 flags（只读、只写、读写、创建、截断 O_TRUNC 等）
   - 引用计数置 1，指向刚才找到的 inode
4. 在**当前进程的文件描述符表**里，找一个最小的空闲下标，填入指向这个文件表项的指针，这个下标就是 fd
5. 返回 fd 给用户进程

额外考点：

- 如果 flag 带`O_CREAT`：路径找不到文件时，新建 inode、新建目录项；mode 指定新建文件权限
- 如果 flag 带`O_TRUNC`：打开时把文件长度截断为 0（清空原有内容）
- ✅ 父子进程 fork 会复制 fd 表，**指向同一个文件表项，共享同一个 offset**
- ❌ open 不会拷贝文件内容到用户缓冲区

---

## 2. read(fd, buf, count)

作用：**从已打开的文件中读取数据，拷贝到用户态缓冲区 buf**

> 
> fd 必须是 open 成功返回的合法描述符

执行步骤：

1. 校验 fd 是否合法，找到进程 fd 表 → 找到对应的文件表项 → 找到 inode
2. 拿文件表里面的**当前文件偏移 offset**，向 inode 查询：这个偏移对应磁盘上哪些数据块
3. 内核先看页 Cache（高速缓存）：
   - 命中：直接从页缓存里拿数据
   - 缺失：发起磁盘 I/O，把磁盘块读到内核页 Cache
4. 将 Cache 里的数据拷贝到**用户态 buf**（内核→用户空间拷贝），最多读 count 字节
5. 更新文件表项里的 offset：offset += 本次实际读到的字节数
6. 返回值：实际读到的字节数；读到文件末尾返回 0；出错返回 - 1

关键点：

- read**不会自动重置偏移**；多个进程共享文件表项时，read 会互相影响 offset（经典考题）
- 读磁盘是**内核缓存机制**，不是每次 read 都直接访问磁盘
- 返回值 ≤ count，不一定一次性读完 count 个字节

---

## 3. write(fd, buf, count)

作用：**把用户缓冲区 buf 的数据写入文件（先写到内核页缓存，延迟刷盘）**

执行步骤：

1. 校验 fd，找到 fd 表→文件表项→inode，检查打开模式是否允许写
2. 如果打开时带 O_APPEND：每次写之前，自动把 offset 挪到文件末尾
3. 将用户 buf 的数据拷贝到内核页 Cache
4. 更新文件表中的 offset：offset += 本次写入字节；同时更新 inode 里面的文件大小
5. 返回成功写入的字节数；出错返回 - 1

> 
> 注意：默认 write 写完**不一定立刻落盘**（延迟写）；由内核后台进程 pdflush/kswapd 定时刷到磁盘；可以用 fsync 强制刷盘

高频坑：

- O_APPEND 保证追加写原子性，多进程追加写不会互相覆盖
- 只修改页缓存，inode 磁盘副本、磁盘数据块不会马上更新

---

## 4. close(fd)

作用：**断开进程和文件的联系，释放资源**，不是删除文件！

执行步骤：

1. 根据 fd，在进程 fd 表找到指向的文件表项
2. 文件表项的**引用计数 -=1**
3. 如果引用计数 > 0：说明还有别的 fd（别的进程 / 本进程别的 fd）指向这个文件表，**只清除当前进程 fd 表里面该项，直接结束**，inode、文件表都保留
4. 如果引用计数 == 0：
   - 释放这个全局文件表项
   - 再看 inode 的引用计数：inode 引用计数 = 0，才释放内存 inode（磁盘上 inode 和文件内容还在！unlink 才删磁盘文件）
5. 把进程 fd 表对应的条目标记为空闲，fd 回收，可以后续 open 复用
6. 返回 0 成功，-1 失败

重点区分：

- close 只是关闭本次打开的流；**不删除文件**
- unlink 才删除目录项，inode 链接数减 1；链接数 = 0 且没有进程打开文件时，磁盘空间才真正回收

# 一张浓缩对比（背诵版）

表格

| 系统调用 | 核心目的           | 关键操作                                          | 主要修改对象               |
| -------- | ------------------ | ------------------------------------------------- | -------------------------- |
| open     | 打开文件，获取 fd  | 查目录项、找 inode、新建文件表项、分配 fd         | fd 表、全局文件表          |
| read     | 读数据到用户缓冲区 | 按 offset 找块、Cache、内核→用户拷贝、移动 offset | 文件表里面的 offset        |
| write    | 用户数据写入文件   | 用户→内核 Cache 拷贝、更新 offset、更新文件大小   | offset、inode 大小、页缓存 |
| close    | 关闭文件，释放引用 | 文件表引用计数减一、回收 fd                       | fd 表、文件表引用计数      |

# 408 选择题经典坑汇总

1. open 不读取文件内容到用户区 ✔
2. read/write 操作的偏移量保存在**文件表项 file 里，不在 inode、不在 fd 表**（超级高频考点！）
3. fork 复制 fd，共享同一个 file、同一个 offset
4. close 只是减引用计数，不等于删除文件；unlink 才删目录项
5. write 默认写缓存，不是直接写磁盘
6. O_APPEND 是在 write 的时候自动跳到末尾，不是 open 的时候固定 offset 不变
