这篇说明提供一份适用于当前网站的笔记模板。之后新建笔记时，可以复制文中的模板，替换标题、日期、标签和正文，再按需删掉不适用的章节。

## 新建笔记的文件位置

建议使用下面的目录形式：

```text
src/content/notes/<英文短 slug>/index.md
```

例如主题是「C 语言指针」，可以把目录命名为 `c-language-pointer`。目录名会成为笔记的网址段；发布后地址形式为 `/personal-website/notes/c-language-pointer/`。标题可以使用中文，slug 建议使用稳定、简短的小写英文和连字符。

## 当前支持的配置

每篇笔记开头的 YAML 区域称为 frontmatter。它由两行 `---` 包住，用来填写列表、页面标题和筛选所需的信息。

| 字段 | 是否必填 | 作用 |
| --- | --- | --- |
| `title` | 必填 | 笔记标题，用于详情页标题和列表链接。 |
| `description` | 必填 | 一两句话的摘要，用于列表卡片和页面描述。 |
| `pubDate` | 必填 | 首次发布的日期，使用 `YYYY-MM-DD` 格式。 |
| `updatedDate` | 可选 | 发生实质内容更新时记录的日期；只改错别字通常不必更新。 |
| `draft` | 可选，默认 `false` | 设为 `true` 时，笔记不会进入列表或生成详情页；准备公开时设为 `false`。 |
| `tags` | 可选，默认空数组 | 可跨笔记、思考和项目使用的主题标签。 |
| `category` | 可选 | 笔记的主要分类。标签适合描述多个主题，分类表示这篇笔记最主要的归属。 |
| `series` | 可选 | 系列的稳定标识符；相同标识符的公开内容会归入同一系列页。 |
| `seriesTitle` | 可选 | 系列的显示名称；留空时使用 `series` 标识符。 |
| `seriesOrder` | 可选 | 系列内正整数顺序；未填写的文章排在显式顺序之后，并按发布日期从早到晚排列。 |
| `project` | 可选 | 所属项目的内容 id，例如项目目录名 `personal-website`。 |
| `related` | 可选，默认空数组 | 显式关联其他笔记、思考或项目，填写 collection 和内容 id。 |

笔记、思考和项目的可复制模板分别位于仓库根目录的 `templates/notes.md`、`templates/thoughts.md`、`templates/projects.md`。普通写作使用 `.md` 即可；只有确实需要在正文中组合文章专属组件时再考虑 `.mdx`，这些组件应放在对应文章目录的 `components/` 子目录中。

## 可复制的完整模板

下面的模板覆盖当前笔记 schema 支持的全部字段和一套可选正文结构。注释放在 YAML 注释和 HTML 注释中：复制到自己的文件后可以保留，也可以删除。方括号中的提示文字需要替换；不适用的正文章节可以删掉。

````md
---
# `title`：必填。详情页主标题和列表链接会使用它；写清楚主题即可。
title: "填写笔记标题"

# `description`：必填。用一两句话概括笔记要解决的问题或主要结论。
description: "填写这篇笔记的简短摘要。"

# `pubDate`：必填。首次发布日，必须写成 YYYY-MM-DD 日期格式。
# 复制模板时请改成这篇笔记实际的发布日期。
pubDate: 2026-09-26

# `updatedDate`：可选。只有内容有实质更新时才填写；不需要时保持注释状态。
# updatedDate: 2026-09-26

# `draft`：可选，默认 false。写作期间建议设为 true，准备公开时改为 false。
# 草稿不会出现在笔记列表，也不会生成公开详情页。
draft: true

# `tags`：可选，默认 []。填写零个或多个跨内容类型主题标签。
# 暂时没有合适标签时保留 []；有标签时可以改成下面的列表形式。
tags:
  - "填写标签"
  - "填写另一个标签"

# `category`：可选。只用于笔记，填写单一主要分类；没有分类就删除此行。
category: "填写分类"

# `series`：可选。填写稳定的系列标识符；暂时不需要系列时删除或注释。
# series: "data-structures"

# `seriesTitle`：可选。系列的可读名称；留空时网站显示 `series` 标识符。
# seriesTitle: "数据结构学习"

# `seriesOrder`：可选。系列内的正整数顺序；未填写的内容按发布日期从早到晚排列。
# seriesOrder: 1

# `project`：可选。填写所属项目在 src/content/projects 下的目录 id。
# project: "personal-website"

# `related`：可选。显式关联内容；collection 为集合名，id 为文章目录 id。
# related:
#   - collection: "notes"
#     id: "sorting-algorithms"
---
````

## Markdown 与排版提示

- 标题层级从 `##` 开始，页面标题已由 `title` 提供。
- 无序列表使用 `-`，有序步骤使用 `1.`；引用使用 `>`。
- 行内代码用单个反引号，例如 `` `npm run build` ``；多行代码用围栏并注明语言，如 ` ```ts ` 或 ` ```c `。
- 数学公式支持 `$公式$` 和 `$$独立公式$$`。代码块由 Shiki 高亮。
- 当前项目尚未接入 Mermaid 图表渲染；`mermaid` 代码块暂时只会作为代码显示，等渲染功能接入后再用于正式图表。

## 从模板发布一篇新笔记

1. 新建 `src/content/notes/<新 slug>/index.md`，把上方代码块完整复制进去。
2. 修改 `title`、`description`、`pubDate`、`tags` 和 `category`，删掉不需要的可选字段和正文小节。
3. 写作期间保留 `draft: true`。运行 `npm run dev`，使用终端显示的本地地址预览。
4. 准备发布时把 `draft` 改成 `false`，保存后提交并推送；GitHub Actions 构建成功后，笔记会出现在列表和对应详情页。
