> 产生方式：`fork()`，调用 fork 的是**父进程**，新生成的是**子进程**

## 1. 资源、地址空间关系（重点）

1. fork 刚返回瞬间：**子进程是父进程的副本**
   - 复制：代码段、数据段、堆、栈、PCB 里大部分属性、打开的文件描述符、信号处理方式、当前工作目录
   - 现代 Linux：**写时复制 COW**，不是立刻全部拷贝物理内存；父子先共享同一份物理页，只有某一方修改页面时，才单独复制该页
   - 不共享：**PID（进程 ID）、PPID（父进程 ID）**；各自独立的进程，有独立虚拟地址空间
2. PPID：子进程的 PPID = 父进程 PID；父进程不知道子进程 PID 需要 fork 返回值获取

## 2. 执行流关系

- fork 之后，**父子两个进程并发、独立调度，谁先运行不确定（调度器决定）**
- 同一个代码，从 fork 返回处**分别继续往下执行**
  - 父进程 fork 返回：子进程 pid（正数）
  - 子进程 fork 返回：0
- 没有先后必然顺序，不要默认父先跑

## 3. 生命周期、僵尸进程、孤儿进程（高频考点）

✅ 正常情况：父进程调用 `wait() / waitpid()`，等待子进程结束，回收子进程 PCB 资源

- **子进程先退出，父进程还在、但没有 wait** → 子进程变成**僵尸进程 (zombie)**
子进程已经结束，但是 PCB 没有被回收，残留在内核。
- **父进程先退出，子进程还在运行** → 子进程变成**孤儿进程 (orphan)**
操作系统会把孤儿进程的父进程改为 **init 进程（PID=1）**，由 init 负责后续回收。

## 4. 文件描述符（常考）

fork 复制文件描述符表，**父子共享同一个文件表项**：文件偏移量、打开标志是共享的！

> 
> 一个进程修改文件指针，另一个进程看到新的偏移。

## 5. 信号关系

- 父进程可以给子进程发信号；
- 子进程退出时，会向父进程发送 `SIGCHLD` 信号，通知父进程回收。

## 6. 一句话对比背诵清单

表格

| 项目         | 父子进程                            |
| ------------ | ----------------------------------- |
| PID          | 不同，子 PPID = 父 PID              |
| 虚拟地址空间 | 独立；fork 初态副本，COW 共享物理页 |
| 代码         | 同一份代码，两个执行流              |
| 调度         | 独立、并发，顺序不确定              |
| 文件表项     | fd 表复制，共享文件偏移             |
| 资源回收     | 父 wait 回收子；父早死则 init 领养  |

## 7. 408 选择题坑点

1. ❌ 错误：父子进程共享地址空间；✅ 虚拟地址空间独立，COW 只是物理页临时共享
2. ❌ 错误：fork 后父一定先执行；✅ 调度顺序不确定
3. ❌ 错误：僵尸进程是进程还在运行；✅ 僵尸进程已经结束，PCB 未回收
4. ❌ 错误：孤儿进程会变成僵尸；✅ 孤儿由 init 收养，正常结束后 init 自动回收，不会僵尸
