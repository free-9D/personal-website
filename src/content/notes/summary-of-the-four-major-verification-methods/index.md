> 408 必考就这 4 种：**奇偶校验、CRC 循环冗余校验、海明校验、校验和**。
> 结构统一：基本思想 → 校验码生成 → 接收端校验 → 适用场景 → 优缺点

## 一、奇偶校验（Parity Check）

### 基本思想

在原始数据位后面增加**1 位奇偶校验位**，让整个码字中「1 的个数」满足奇数或者偶数。

- 奇校验：整个码字中 1 的总数 = 奇数
- 偶校验：整个码字中 1 的总数 = 偶数

### 校验码生成

1. 统计原始数据里面 1 的个数
2. 奇校验：1 的个数为偶数 → 校验位填 1；为奇数 → 校验位填 0
3. 偶校验：1 的个数为奇数 → 校验位填 1；为偶数 → 校验位填 0

> 
> 例（偶校验）：数据 `1011001`，里面有 4 个 1（偶数），校验位 = 0，发送码字：`1011001 0`

### 接收端检验

接收全部码字，重新统计 1 的个数：

- 偶校验：1 的总数是偶数 → 认为无错；奇数 → 出错
- 奇校验：1 的总数是奇数 → 认为无错；偶数 → 出错

### 适用场景

早期串口通信（RS232）、内存简单检错；**只检错，不能纠错**。

### 优缺点

✅ 优点：算法最简单、硬件实现极快，只需要异或门
❌ 缺点：

1. **只能检出奇数个比特错误（1、3、5… 位错）**；偶数个比特翻转检测不出来
2. 不能定位错误位置，无法纠错
3. 检错能力很弱

> 
> 补充：**二维奇偶校验（方阵奇偶）**
> 把数据排成矩阵，每行做奇偶、每列也做奇偶。可以纠正**单比特错**，检出大部分双比特错；但特殊双比特错依然漏检。408 选择题偶尔考。

## 二、CRC 循环冗余校验（Cyclic Redundancy Check，循环码）【最高频】

### 基本思想

把二进制数据看成多项式，用**模 2 除法（异或，无借位减法）**除以一个预先约定的生成多项式 G (x)，得到余数作为 CRC 校验码（余数位数 = G (x) 最高次幂 r）。

> 
> 模 2 运算：异或，`1⊕1=0，1⊕0=1`，不进位、不借位

### 校验码生成步骤

设原始数据 M，生成多项式 G (x)，r 是 G 的阶数（校验位长度 = r）

1. 在 M 后面**补 r 个 0**，得到 `M<<r`
2. 拿 `M<<r` 和 G 对应的二进制串做**模 2 除法**
3. 得到的 r 位余数就是 CRC 校验码；**余数不能全 0**
4. 把余数替换掉末尾补的 r 个 0，组成最终发送码字 T

举个极简例子：
M=1010，G (x)=x³+1 → G=1001，r=3
M 后面补 3 个 0：1010000，模 2 除以 1001，得到余数，拼接发送。

### 接收端检验

接收码字 R，同样拿 R 模 2 除以 G 对应的二进制：

- 余数 = 0：判定**没有出错**
- 余数 ≠ 0：判定出错

> 
> 重点：CRC**只能检错，不能自动纠错**（除非配合额外机制，408 默认 CRC 不纠错）

### 适用场景

局域网（以太网、802.3）、USB、磁盘扇区、HDLC 帧、数据链路层主流校验。

### 优缺点

✅ 优点：

1. 检错能力很强：可以检出**所有≤r 位的错、大部分大于 r 位的错**
2. 硬件容易实现（移位寄存器 + 异或门），速度快
3. 开销可控，r 一般取 16/32（CRC16、CRC32）
❌ 缺点：
4. 不能纠错，出错之后只能请求重传（ARQ）
5. 存在极小概率漏检（错误图样刚好是 G (x) 倍数，概率很低，工程上可接受）

> 
> 408 必背考点：CRC 是**数据链路层最常用**；模 2 除法、生成多项式；r 位校验码，余数 r 位。

## 三、海明校验（Hamming Code，汉明码）【唯一可以纠错的】

### 基本思想

插入**多个校验位**，每个校验位负责监督一部分信息位；利用多组奇偶校验的结果，形成**错码位置的二进制编号**，定位哪一位出错，然后翻转纠错。

> 
> 核心公式：`2^k ≥ k + n + 1`
> n：信息位位数；k：校验位位数；k 个校验位放在 2⁰,2¹,2²… 位置（第 1,2,4,8,16… 位）

### 校验码生成

1. 根据 n 算出需要的校验位 k
2. 校验位放在下标为 2 的幂的位置，剩下位置填信息位
3. 每一个校验位 Pi，对所有**下标二进制第 i 位为 1**的位置做偶校验（默认偶校验）
4. 算出每个 Pi 的值，填入对应位置，得到海明码字

例：n=4，算出 k=3，位置 1 (P1),2 (P2),3 (D1),4 (P3),5 (D2),6 (D3),7 (D4)
P1 监督：1,3,5,7
P2 监督：2,3,6,7
P3 监督：4,5,6,7

### 接收端检验

接收后，分别重新计算每组奇偶，得到校正因子 S₃S₂S₁

- S=000：无错
- S≠000：S 的十进制值就是出错的位号；把这一位取反，完成纠错

> 
> 注意：标准海明码**只能纠正 1 位错，检测不出 2 位错**；扩展海明码（增加一位全校验位）可以做到：纠 1 检 2，408 大题考过！

### 适用场景

早期内存 ECC、存储器；现在计网里很少用，更多是组成原理、校验码大题。

### 优缺点

✅ 优点：**可以自动纠正单比特错误**，不需要重传
❌ 缺点：

1. 校验位开销大：信息位越长，校验位 k 增长慢但占比高于 CRC
2. 硬件比 CRC 复杂
3. 普通海明码无法区分「1 位错」和「2 位错」，2 位错会误判成某个 1 位错，改错；扩展海明才可以纠 1 检 2
4. 不适合高速链路，网络层 / 链路层几乎不用

## 四、校验和（Checksum，因特网校验和）【网络层】

### 基本思想

把数据按固定长度（IP 是 16bit）分成若干个字，**反码求和**，和的反码作为校验和。

> 
> 重点：不是普通加法，是**反码加法（循环进位）**，这是和 CRC、奇偶最大区别

### 校验码生成（IP 首部校验和为例）

1. 把 IP 首部按 16bit 分组，校验和字段先置 0
2. 所有分组做**反码相加**（最高位进位加到最低位）
3. 最终总和取反，填入校验和字段，发送

### 接收端检验

接收方把包括校验和在内的所有 16bit 分组继续反码相加：

- 结果全 1（FFFF）：无错
- 不是全 1：出错，丢弃报文，不重传（IP 是无连接）

### 适用场景

IP 首部、UDP、TCP 首部校验（传输层 + 网络层）；**只校验首部，TCP/UDP 可以选择校验数据**。

### 优缺点

✅ 优点：

1. 软件实现超级简单，适合 CPU 计算，不需要特殊硬件
2. 开销小，固定 16bit
❌ 缺点：
3. 检错能力弱：很多错误组合加起来依然和不变，会漏检
4. **不能纠错**，只能检错
5. 不适合链路层，链路层优先 CRC

# 408 高频坑点提醒（一定要分清）

1. 链路层帧校验 **FCS 就是 CRC**，不是校验和！很多人混
2. IP/TCP/UDP 用的是**因特网校验和**，不是 CRC
3. 海明码属于**纠错码**；CRC、奇偶、校验和都是检错码
4. CRC 余数 r 位，生成多项式 G (x) 最高次就是 r；补 r 个 0 再除
5. 校验和是**反码求和**，不是模 2，也不是普通补码加法
