## 1. IPv6 地址

1. 地址长度：128 bit。
2. 表示形式：冒分十六进制，分为 8 组，每组 4 个十六进制数。
3. 压缩规则
   - 每组内部前导 0 可以省略；
   - 连续多组全 0，可以压缩成 `::`；**一个地址中最多只能有一处 `::`**。
4. 地址类型
   - 单播地址：标识单个接口，一对一通信；
   - 组播地址：一对多交付；IPv6**不存在广播地址**；
   - 任播地址：分配给一组接口，路由转发到距离最近的接口；**仅可作目的地址，不能作为源地址**。
5. 特殊地址
   - `::/128`：未指定地址，不能用作目的地址；
   - `::1/128`：环回地址；
   - `fe80::/10`：链路本地地址，仅在本链路有效，路由器不会转发该地址的报文。

## 2. IPv6 基本首部

1. 基本首部固定长度：40 字节，无选项字段，所有可选功能放在扩展首部。
2. 基本首部字段
   - 版本 Version：固定值 6；
   - 流量类别 Traffic Class：用于 QoS 标记；
   - 流标签 Flow Label：标识一条流，IPv4 无此字段；
   - 载荷长度 Payload Length：表示扩展首部 + 上层数据的长度，不含 40B 基本首部；
   - 下一个首部 Next Header：指明后面紧跟的是扩展首部，或是 TCP/UDP 等上层协议；
   - 跳数限制 Hop Limit：每经过一台路由器减 1，减到 0 丢弃；
   - 源地址、目的地址：各 128bit。
3. IPv6 基本首部**没有首部校验和字段**。

## 3. 扩展首部

1. 扩展首部链式组织，依靠 Next Header 字段串联；
2. 常见扩展首部：逐跳选项、目的选项、路由首部、分片首部、AH、ESP；
3. 扩展首部不属于基本首部。

## 4. 分片机制

1. IPv6 只允许**源主机进行分片**，转发途中的路由器不允许分片；
2. 当路由器收到报文超过出接口 MTU 时，丢弃报文，并通过 ICMPv6 向源端返回 “报文过大”，由源端重新分片；
3. 分片信息存放在分片扩展首部；重组仍然只在目的主机完成。

## 5. ICMPv6 与邻居发现 NDP

1. ICMPv6 替代 IPv4 的 ICMP；
2. NDP（邻居发现协议）属于 ICMPv6，**IPv6 不再使用 ARP**；
3. NDP 功能：地址解析（IPv6→MAC）、路由器发现、邻居可达性检测、重复地址检测 DAD；
4. PMTU 发现由 ICMPv6 实现。

## 6. IPv4 向 IPv6 的过渡技术

1. 双协议栈：节点同时支持 IPv4 和 IPv6 协议栈；
2. 隧道技术：将 IPv6 报文封装在 IPv4 报文中，穿越 IPv4 网络；
3. NAT64：协议转换技术，实现纯 IPv6 节点和纯 IPv4 节点互通。

## 7. 和 IPv4 的重要对比要点

1. IPv4 首部可变长；IPv6 基本首部固定 40B；
2. IPv4 有广播；IPv6 无广播，用组播；
3. IPv4 有 IP 首部校验和；IPv6 基本首部无校验和；
4. IPv4 路由器可以分片；IPv6 路由器不分片；
5. IPv4 用 ARP；IPv6 用 NDP；
6. IPv4 是 TTL；IPv6 是 Hop Limit，功能都是跳数限制。

## 8. 其他细节

1. 流标签：用来标识属于同一个流的数据包，方便路由器统一处理；
2. 任播地址：一组接口共享，选最近一个；不可做源地址；
3. 上层 TCP、UDP、ICMPv6 仍然保留校验和。
